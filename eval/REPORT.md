## Method

- **161 requests**: the 13 hand-made v1 requests, 9 new inbox requests written for the demo, and 139 generated across 14 categories (kitchen vs bath, size, timeline, out-of-area, spam, incomplete, duplicates, urgent, investors, remodelers, not-a-fit, and tricky negatives such as a real lead with a link or a prompt-injection line).
- **Labels come from policy, not code.** Each scenario in the generator states the action QBC's written routing rules require (settled Nov 11, 2026). The generator imports none of the triage code.
- **Holdout.** 40 generated requests use separate phrasing banks (different spam pitches, urgent wording, neighborhoods, towns) and were committed before any fix. While fixing, only the dev split was printed (`npm run eval -- --dev`).
- **v1 on raw forms.** v1 expected clean fields, so `eval/baseline-v1.js` maps each form the way a minimal form handler would (location as typed, `parseInt` on the units box, blank = missing). It cannot produce Spam, Duplicate or Not a fit, so those count against it; the "real leads only" row compares like with like.
- **Harmful vs recoverable.** A miss is harmful if approving it as proposed would screen out a real lead, merge a new request away, tell an in-area customer to measure their own kitchen, or offer a measure outside the area. Everything else costs one extra question or is junk a person spots on review.

## Limits

- **Same author for data, labels and rules.** The generator, the labels and the fixes were written in one session by the same author (Claude, directed by Alex). The holdout guards against tuning to exact phrasings, but it is not a blind test. Treat the numbers as a regression suite for the written policy, not as real-world accuracy.
- **Synthetic only.** No real request has been routed. Real intake will have phrasings this set does not.
- **The place table is a sample.** Towns outside it are asked for a ZIP rather than guessed; a real deployment would load a full ZIP-to-county crosswalk.
